# Troubleshooting

[Setup](setup.md) · [Configuration](configuration.md) · [Privacy](privacy.md)

Start with `uv run --locked dms check`. It reports local readiness without spending Gemini quota or probing the camera by default. For runtime state, open Setup and inspect `/api/v1/health` in the browser while the server is running. Keep sensitive payloads out of public issues.

| Symptom                                     | Likely cause / next action                                                                                                                                                                     |
| ------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dms` not found                             | Run from the source checkout using `uv run --locked dms --help`. Use `uv sync --locked` if dependencies/entrypoints have not been installed.                                                   |
| Wrong Python                                | Run `uv python install 3.12` and synchronize. Project metadata accepts Python 3.12 only.                                                                                                       |
| Command uses an old moved-folder path       | Virtualenv entrypoint scripts can retain absolute paths. Stop DMS and recreate the virtualenv through uv rather than copying a previous machine's `.venv`. Preserve `.env`, models, and data.  |
| Native Windows `fcntl` error                | Current runtime is Unix-specific. This is an implementation limitation, not a missing Python package.                                                                                          |
| Linux import error for GL/EGL/audio         | Install the Ubuntu libraries listed in Setup, or equivalent packages for your distribution.                                                                                                    |
| Port already in use                         | Another process owns the port. Stop the known DMS instance gracefully, or select an unused `WEB_PORT` and restart. Do not kill unrelated processes blindly.                                    |
| “Already running with this data directory”  | Another process owns the lock. Stop that instance first. Removing the lock file while it is held is not a safe fix.                                                                            |
| Face model missing/checksum mismatch        | Run `uv run --locked dms setup-models`; it restores the manifest asset explicitly.                                                                                                             |
| Camera unavailable                          | Grant permission to the launching app, close competing camera apps, and check `CAMERA_INDEX`. `dms check --probe-camera` opens the configured device intentionally.                            |
| No face / empty measurements                | Improve face visibility, lighting, and camera position. Glasses, occlusion, and pose can affect tracking. Unavailable is not a low-risk measurement.                                           |
| Calibration makes no progress               | Start a live session, keep pitch/yaw within the frontal range and eyes naturally open. Valid time accumulates only on accepted samples; retry before/after the 60-second timeout as indicated. |
| Settings changes seem ignored               | Stop the active session before saving. Existing `settings.json` fields override `.env` at CLI startup. New session creation applies monitoring preferences.                                    |
| Audio test returns 409                      | Enable audio in Settings while idle and save.                                                                                                                                                  |
| Audio is queued but silent                  | Check macOS output volume/device and health errors. `say` is macOS-only; Linux visual alerts do not imply speech support.                                                                      |
| Voice unavailable                           | Install the `voice` extra and model explicitly; grant microphone access. The first request can take longer while the model loads. Typed questions still work.                                  |
| No text after recording                     | Check default input and microphone permission; silence may correctly produce an empty transcript because VAD is enabled.                                                                       |
| Knowledge remains lexical                   | This is a supported mode. Install the `knowledge` extra/model for dense retrieval. A cold load may take time; unavailable dependencies fall back locally.                                      |
| Changed knowledge file not reflected        | Restart the application. Assistant-settings reload does not reingest the corpus.                                                                                                               |
| Gemini “not configured”                     | Install the extra, set backend `GEMINI_API_KEY`, and reload assistant settings. Never add the key to frontend files.                                                                           |
| Model/key edit not applied                  | An exported environment variable overrides `.env`. Inspect how the launching shell is configured without printing the secret. Reload only Gemini fields or restart for other changes.          |
| Gemini falls back locally                   | Inspect the limitation: key/model access, provider quota, timeout, invalid cited response, or local spacing/cap. Wait if appropriate; do not reset usage counters to bypass caps.              |
| Reload returns 409                          | Wait for active/queued cloud work to finish, then retry. Monitoring can continue.                                                                                                              |
| “Assistant is busy”                         | The three waiting slots are occupied. Local status and monitoring are separate from cloud generation.                                                                                          |
| Replay ends with unavailable state          | Expected after the final synthetic frame. Use Stop session to finalize and view the report.                                                                                                    |
| No sessions / no score trend                | Confirm a session was started and stopped; fewer/invalid samples can produce empty data. Storage path changes select a different history directory.                                            |
| Tracking coverage lower than expected       | It is the fraction of stored samples in exactly `monitoring`, not a time-integrated camera accuracy figure; degraded/calibrating samples are excluded.                                         |
| Storage failure                             | Stop monitoring; check disk space, directory permissions, and health. Preserve data before repair. Failed writes are not automatically reconstructed.                                          |
| Browser reports disconnected/stale          | Confirm the server is running and the page uses the configured loopback port. Reconnect does not create missing measurements.                                                                  |
| WebSocket rejected                          | Use the same allowed loopback origin and configured port. Origin-less third-party clients must supply an approved Origin.                                                                      |
| Native test aborts in an automation sandbox | MediaPipe native initialization may need normal local process permissions. Do not remove the test or weaken the application CSP to hide an environment failure.                                |

If the issue persists, reproduce with synthetic replay and optional components disabled where possible. Report whether the failure happens in setup, startup, session creation, inference, storage, or optional assistance. Avoid claiming a camera/perception bug from replay alone: replay bypasses the vision worker.
